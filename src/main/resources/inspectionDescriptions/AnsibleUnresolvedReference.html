Reports Ansible roles, includes and file references that resolve to nothing.

A reference is reported when no file on Ansible's own search path can satisfy it — a roles: entry with no matching directory under roles/ or roles_path, an include_tasks: naming a file that is not beside the role's tasks/ or the playbook, a template: src: missing from templates/ and files/, or a notify: naming no handler.

A Jinja-templated target is treated differently. include_vars: "{{ ansible_os_family }}.yml" legitimately has a set of answers, and is left alone as long as at least one candidate file exists. It is reported only when the pattern matches nothing at all, because then no possible fact value would make it resolve.

Anything whose value Ansible can only know at run time is never reported. The inspection reads the same resolution model as Ctrl/⌘+Click and completion, so it cannot disagree with what navigation does.

A false positive here usually means the project's layout is not the one the plugin inferred — most often a roles_path in an ansible.cfg the plugin did not find, or one meant to be resolved from a working directory other than the config's own.
